## 1. 技术栈与工程结构

- Vue 3（Composition API + `<script setup>`）+ TypeScript + Vite
- UI：Element Plus（仅用 `el-tooltip/el-popover/el-empty` 等基础件；消息流与卡片全部自绘，保证控制台风格统一）
- 图表：ECharts（vue-echarts 封装）；状态：Pinia；路由：vue-router
- WebSocket：原生 API 自封装（不引第三方库，便于控制重连与消息分发）
- 等宽字体：`"JetBrains Mono", Consolas, monospace`（本地 fallback，不引外部字体文件，保证离线可演示）

## 3. 布局系统

### 3.1 端形态决策（已定稿）

响应式 Web、PC 优先：一套 Vue3 代码，≥1024px 控制台布局，<1024px 折叠为单栏（APP 形态）；不做 Electron/Tauri（M4 可套壳，约 1 天，不封死路线）。

### 3.2 断点

| 断点 | 行为 |
|---|---|
| ≥1280px | 双栏 + 可展开透视抽屉（抽屉宽 360px，主列不挤压，整体平移） |
| 1024–1279px | 双栏；抽屉展开时**覆盖**主区右侧（遮罩） |
| <1024px | 单栏 APP 形态：侧栏收进左上角抽屉；审批卡/MFA 全屏覆盖 |

### 3.3 PC 控制台布局（≥1024px）

```
┌───────────────────────────────────────────────────────────────────┐
│ 标题栏 38px（窗口点 · 会话标题，仅浏览器全屏演示时隐藏）               │
├──────────────┬────────────────────────────────────────────────────┤
│ 侧栏 240px    │ 主线程列（max-width 860px，水平居中，两侧留白）        │
│  §4.1        │  · 消息流（§4.2~4.11）                               │
│              │  · 底部输入框（§4.12）                                │
├──────────────┴────────────────────────────────────────────────────┤
│ 状态栏 26px（§4.13）                                                │
└───────────────────────────────────────────────────────────────────┘
   透视抽屉 TraceDrawer：从右缘滑出 360px（§4.14）
```

- 主线程内容列 860px：保证审批卡参数表两列布局不折行；
- 消息流垂直间距 14px（`--sp-3`+2），块与块之间不留气泡式大留白——控制台密度；
- **空会话**（无消息）时主列渲染 ScenarioHub 服务宫格大厅（§4.19）替代消息流——四组七卡第一屏直给（D 组置顶）；首条消息发出后让位消息流，本会话内不再回显。

### 3.4 移动端布局（<1024px）

顶栏 48px（☰ + 会话标题 + 安全状态点）→ 消息流 → 输入框。审批卡/MFA 全屏覆盖层（`--z-mfa-full`）；DAG 待办块、工具块正常内联；透视抽屉不可用时，DAG 详情点开为全屏弹层。

### 3.5 页面路由

| 路由 | 页面 | 说明 |
|---|---|---|
| `/login` | LoginView | 选演示用户（张三）+ 口令 → JWT 存 sessionStorage |
| `/chat` | ChatView | 主战场：消息流 + 全部块组件交互 |
| `/audit/:traceId` | AuditView | 决策链回放（答辩演示用，§4.17） |
| `/im` | MockImView | 模拟 IM 渠道（验证多渠道归一化，§4.18） |

## 4. 组件详细设计

> 每个组件给出：用途 → props → 状态 → 结构/样式 → 交互。props 类型名与 `types/protocol.ts` 对齐。

### 4.1 AppSidebar（侧栏，240px）

- **结构**：品牌区（金色 ◆；文案随模式：管家模式「◆ 智银」/ 透视模式「◆ 智银 Agent」，§11.2#8）→ `＋ 新会话` 按钮 → `◈ 服务大厅` 常驻入口（点击 = 新会话并展示 §4.19 宫格大厅，四组服务随时可重返）→ 「会话」分组列表 → 底部用户信息卡；
- **会话条目 SessionItem**：
  - 两行：标题（13px，`--text-muted`，截断省略）+ 副行（11px `--text-faint`，格式 `状态词 · 相对时间`，状态词 ∈ `等待确认/等待验证/进行中/已完成/已锁定`）；
  - 激活态：`--bg-panel` 底 + 左缘 2px 金色条；
  - 有待办（waiting_confirm/mfa）的会话条目右侧显示对应色圆点（黄/红），切走也可见——防"忘了还有一笔待批转账"；
- **底部用户卡**：`张三 · 尾号 6688` + 状态点行 `● 安全引擎 ● 熔断器 closed`（正常绿 / 异常红）；
- 交互：点击条目切换会话（重新建立 WS）；`＋新会话` 清空 chat store 并新建 session。

### 4.2 ChatThread（消息流容器）

- 职责：消息列表渲染（`v-for` + `MessageItem`）、自动滚动、流式 token 追加；
- 滚动规则：新消息到达时若视口在底部 120px 内 → 平滑滚到底；用户上翻时不抢滚动，右下浮出「↓ 回到底部」小圆钮（`--bg-panel`，32px）；
- 不引入虚拟滚动（单会话消息 <500 条，演示场景足够）。

### 4.3 UserMessage / AgentMessage

| | UserMessage | AgentMessage |
|---|---|---|
| 前缀 | `❯`（金色，bold） | `⏺`（绿） |
| 文本 | `--text-primary` 14px | `--text-secondary` 13.5px，行高 1.75 |
| 流式 | — | token 逐段追加 + 光标 `▍`（`--text-faint` 闪烁 1s）；`final` 到达后光标消失 |

- AgentMessage 支持有限 Markdown：加粗、行内 code（`--bg-panel` 底 + mono）、有序/无序列表；不渲染链接/图片（安全收敛）；
- 时间戳不逐条显示（控制台风格），仅日期分隔线 `── 今天 10:42 ──`（`--text-faint` 11px 居中）。

### 4.4 ToolCallBlock（工具调用块）

```
┌──────────────────────────────────────────────┐
│ ⏺ resolve_contact(keyword: "李磊")   ✓ 120ms │
│ ⎿ 2 位匹配：李磊(3821)同事 / 李磊(7790)同学    │
└──────────────────────────────────────────────┘
```

- props：`{ name: string; args: Record<string,unknown>; status: 'running'|'done'|'failed'; durationMs?: number; resultSummary: string }`
- 容器：`--bg-panel` 底、`--border` 描边、`--r-card`、内边距 10×14px；
- 首行 mono 13px `--text-primary`；状态位右对齐：`⠋ 执行中`（黄，旋转）→ `✓ 120ms`（绿）/ `✗ 失败原因`（红）；
- 结果行：`⎿` 引导（`--text-faint`），mono 12px `--text-muted`，最多 3 行，超出折叠为 `⎿ …查看详情`（点击展开 el-popover 显示完整 JSON，等宽）；
- **金额/卡号在 resultSummary 中必须服务端给、原样渲染**（安全设计 §02-7.5 的前端落点）。

### 4.5 TodoDagBlock（DAG 待办清单块）

```
┌──────────────────────────────────────────────┐
│ 执行计划 · DAG                       ⤢ 详情   │
│ ☒ resolve_contact（李磊）                    │
│ ◐ transfer（¥5,000.00 → 李磊·3821）⚠ 等待MFA │
│ ☐ verify_result · reply                      │
└──────────────────────────────────────────────┘
```

- props：`{ nodes: DagNodeProgress[] }`，`DagNodeProgress = { id, label, toolName, status: 'done'|'running'|'waiting_confirm'|'waiting_mfa'|'pending'|'failed'|'compensated' }`
- 状态图标：`☒` done（绿）/ `◐` running（黄脉冲 1.2s）/ `⚠` waiting（黄/红按风险）/ `☐` pending（faint）/ `✗` failed（红）/ `↩` compensated（muted）；
- 右上角 `⤢ 详情` → 打开 TraceDrawer 的 DAG 图页签；
- 节点状态翻转有 `--motion` 过渡；**这是"自主规划"考点在消息流中的内联证据**。

### 4.6 ApproveCard（审批卡，黄/红变体）★核心交互

```
┌────────────────────────────────────────────────┐
┃ 需要您的确认 · 黄色操作                04:32 ⏳ │
┃ 工具        transfer                           │
┃ 收款人      李磊（尾号 3821 · 同事）            │
┃ 金额        ¥200.00                            │
┃ 备注        聚餐 AA                            │
┃ 后果        实时到账，无法撤回                   │
┃ ❯ 1. 确认转账                                  │
┃   2. 取消                                      │
└────────────────────────────────────────────────┘
```

- props：`ConfirmCardPayload = { actionId, riskLevel: 'yellow'|'red', title, detail: {label,value}[], consequence, expiresInSec, upgradeReasons?: string[] }`
- 容器：`--bg-panel` + `--border-strong` 描边 + **左缘 3px 风险色条**（黄 `--yellow` / 红 `--red`）；红变体标题后缀 `· 红色高危`；
- 参数表：label 列 96px `--text-muted`，value 列 mono `--text-primary`；金额值黄色 `--yellow`（红卡金额红色）；
- **动态升级说明**：`upgradeReasons`（如「当日累计转账 ¥5,200 超阈值 → 由黄升红」）以 `⚠` 引导一行显示在参数表下方——裁决透明的可视化；
- 选项行：当前高亮项 `❯` 前缀 + `--text-primary`；未选项缩进 14px `--text-muted`；鼠标悬停切换高亮，点击 = 选择并提交；
- 倒计时：右上角 mono `mm:ss`，`expiresInSec` 本地递减；<60s 变红；归零 → 卡片置灰显示「已过期」，按钮禁用（服务端同时置 expired，前后端一致）；
- 提交后：卡片整体降透明度至 .55，标题变「已确认 ✓」（绿）/「已取消」（muted），选项区移除——**防重复点击**；
- 键盘：`↑/↓` 移动高亮，`Enter` 提交，`Esc` = 取消（同点 2）。

### 4.7 MfaBlock（MFA 验证块，红色调）

```
┌────────────────────────────────────────────┐
┃ 🔐 多因子认证 · 短信验证            02:58 ⏳ │
┃ 验证码已发送至 138****6688                  │
┃ ┌──┬──┬──┬──┬──┬──┐                       │
┃ │1 │3 │9 │  │  │  │   剩余尝试：2 次        │
┃ └──┴──┴──┴──┴──┴──┘                       │
┃ [确认验证]   没收到？56s 后重发              │
└────────────────────────────────────────────┘
```

- props：`MfaRequestPayload = { challengeId, type: 'sms'|'face', targetMasked, expiresInSec, attemptsLeft }`
- 容器同 ApproveCard，左色条红色；
- 六格输入：每格 36×44px、mono 20px、`--bg-base` 底、聚焦格描边 `--red`；自动右移、粘贴 6 位自动拆分、退格回退；
- `face` 变体：中央「📷 模拟人脸采集」圆钮，点击 1.2s 扫描动画 → 成功；
- 错误：输入框整体水平抖动 0.3s + 下方红字 `验证码错误，剩余 N 次`；`attemptsLeft` 归零 → 服务端锁会话，LockScreen 接管；
- 「重发」倒计时 60s mono；整个块提交后变「已通过 ✓」绿调降透明；
- 移动端：`--z-mfa-full` 全屏覆盖。

### 4.8 DisambiguationBlock（消歧选项块）

- props：`{ question: string; options: { id, primary, secondary }[] }`
- 结构：问题行（`⏺ 找到 2 位"李磊"，请选择：`）+ 选项列表——每行一个 `--bg-panel` 圆角条，内容 `李磊 · 尾号 3821`（mono 尾号）+ 右侧 `--text-faint` 备注 `同事`；
- 点击即上行 `user_message`（结构化文本「选择：李磊（尾号 3821）」），块变为单选态（选中行金色描边，其余降透明），不可再点。

### 4.9 ChartBlock（账单图表卡）

- props：`{ charts: ('pie'|'bar')[], seriesData: {...}, anomalies: TxnItem[] }`
- 结构：标题行（如「8 月消费分析」）+ ECharts 容器（高 220px）+ 异常交易子列表；
- 图表配色受控：饼图取 `[#d4af37,#4ade80,#60a5fa,#fbbf24,#a78bfa,#f87171]`，柱图主色 `--brand`；背景透明、坐标轴文字 `--text-muted`——图表必须融入暗色控制台；
- 异常交易条目：`⚠ 09-14 03:22 数码商城 ¥4,999.00`（金额红色 mono），点击展开详情行（商户/卡尾号/「一键挂失」按钮入口——联动演示场景）。

### 4.10 ReceiptBlock（回执块）

## 5. 消息渲染体系（`MessageItem.vue` 分发器）

下行消息统一 `{ type, payload, trace_id?, ts }`，分发表：

| type | 组件 | 要点 |
|---|---|---|
| `stream_token` | AgentMessage（追加） | 累积进 `streamingText`；`final` 收尾 |
| `text` / `final` | AgentMessage | 完整文本消息 |
| `tool_progress` | ToolCallBlock + TodoDagBlock | 携带 node_id/工具名/状态/耗时/结果摘要 |
| `confirm_card` | ApproveCard | payload 即 §4.6 `ConfirmCardPayload` |
| `mfa_request` | MfaBlock | 红色块 + MockSmsPanel 联动 |
| `clarify_options` | DisambiguationBlock | 消歧选择 |
| `chart` | ChartBlock | 图表序列 + 异常列表 |
| `receipt` | ReceiptBlock | 回执 + trace 跳转 |
| `account` | AccountCard | 余额摘要 |
| `locked` | LockScreen | 熔断遮罩 + 输入框禁用 |
| `error` | AgentMessage（红调） | 错误说明 + 建议下一步 |

```typescript
// types/protocol.ts（节选，与 doc 02 §10.1 一致）
type ServerMessage =
  | { type: 'stream_token'; payload: { delta: string } }
  | { type: 'tool_progress'; payload: ToolProgressPayload }
  | { type: 'confirm_card'; payload: ConfirmCardPayload; trace_id: string }
  | { type: 'mfa_request'; payload: MfaRequestPayload }
  | { type: 'clarify_options' | 'chart' | 'receipt' | 'account'; payload: any }
  | { type: 'locked'; payload: { reason: string; unlockAt: number } }
  | { type: 'final'; payload: { text: string } }
  | { type: 'error'; payload: { code: string; message: string } }
type InboundMessage =
  | { type: 'user_message'; text: string }
  | { type: 'action_confirm'; action_id: string; approved: boolean }
  | { type: 'mfa_submit'; challenge_id: string; code: string }
  | { type: 'interrupt'; mode: 'stop' | 'takeover' }
```

**铁律**：卡片关键数据（金额/收款人/卡号）一律来自服务端 payload 直接渲染，绝不从 LLM 文本中解析——前端落实"防幻觉/防篡改"。

## 7. WebSocket 客户端（`ws/client.ts`）

```typescript
class WsClient {
  connect(token: string): void        // ws://host:8200/ws/web?token=...
  send(msg: InboundMessage): void
```

## 8. 关键交互流程

### 8.1 黄色确认（转账 ¥200）

```
用户输入 → [processing] 输入框禁用、⠋
← tool_progress ×2 → TodoDagBlock 两节点 + ToolCallBlock(✓120ms)
← confirm_card → ApproveCard(黄) 弹出、倒计时起
用户 Enter/点击"1" → 上行 action_confirm → 卡片变「已确认 ✓」.55 透明
← tool_progress(n2 ✓) → ← receipt 回执 → [active] 输入框解锁
```

### 8.2 红色 MFA（转账 ¥5000，累计超限升级）

confirm_card（红，附 upgradeReasons）→ 确认 → `mfa_request` → MfaBlock + MockSmsPanel 滑入 → 输码 → 通过 ✓ → 回执；错误 → 抖动 + 剩余次数；3 次失败 → `locked` → LockScreen。

### 8.3 消歧（两个李磊）

`clarify_options` → DisambiguationBlock → 点击其一 → 结构化文本上行 → DAG 继续。

### 8.4 注入攻击被拒（安全演示）

用户粘贴恶意指令 → guard_in 命中 → ← `error`（红调：「检测到可疑指令，已拦截」）+ StatusBar 注入计数 +1 → 累计 3 次 → `locked` → LockScreen + 审计页可见完整拦截链。

### 8.5 审计回放（答辩杀手锏）

ReceiptBlock `[回放]` → AuditView：intent→plan→decision→tool_call→confirm→reply 六类事件时间线，逐条重放点亮——现场证明"决策链路全程可追溯"。

### 8.6 中断与回退

处理中按 `Esc` → 上行 `interrupt(stop)` → DAG 未执行节点标记取消，已执行节点按补偿链逆序回退（TodoDagBlock 节点变 `↩`）→ 回执「已回退」。

### 8.7 场景直达（大厅 → 业务）

空会话 → ScenarioHub 四组宫格可见（7 卡，D 组置顶） → 点击「给李磊转 500，备注生日快乐」chip → 等同手动输入上行 → [processing] → 命中同名联系人 → DisambiguationBlock（§8.3）→ 后续流程与 §8.1 完全一致。大厅发起的任务**不另设协议、不降低任何安全等级**——示例指令只是替用户"打好了字"。

### 11.3 安全 UI 不变量（两模式共同遵守，doc 06 §2.3）

1. 卡片关键数据（金额/收款人/卡号）一律服务端 payload 渲染，LLM 文本永不作为数据源；

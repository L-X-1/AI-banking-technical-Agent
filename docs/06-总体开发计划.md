## 1. 场景同类合并（严格按赛题）

### 1.1 合并三原则

1. **赛题结构一字不动**：六场景名称、能力点、P0/P1/P2 优先级与 doc 01 §1.2 完全一致；doc 05 M3 DoD 九条逐条可验；前端每个场景卡带赛题 `#1~#6` 徽标，评委可对号入座——**合并绝不减少任何考点**。
2. **合并只发生在两层**：① 前端信息架构（分组展示）② 工程复用（组件/工具/安全链路）。
3. **用户心智优先**：分组名用用户语言（"把钱动起来 / 看明白 / 管起来 / 自动办"），不用技术黑话——这是"让用户清晰明确用明白"的第一落点。

### 1.2 合并方案：6 场景 → 4 组

| 组 | 含赛题场景 | 用户心智 | 共性链路 | 权限特征 |
|---|---|---|---|---|
| **A 资金办理** | #1 智能转账 · #3 理财操作 | "把钱动起来" | 裁决 → 确认 → 执行（幂等）→ 回执 | 🟡/🔴 为主 |
| **B 洞察分析** | #2 账单分析 · #5 的订阅识别与续费提醒 | "帮我把钱看明白" | 绿色直通 → 聚合 → 图表 → 可追问 | 全 🟢 |
| **C 卡片与订阅管理** | #4 卡片管理 · #5 的一键取消 | "把长期契约管起来" | 状态卡 → 操作 → 裁决 → 确认 → 刷新 | 🟡/🔴 |
| **D 智能联动** | #6 跨场景联动 | "一句话，自动办一串事" | 事件 → 多步 DAG → 定时任务 → 触发通知 | 按子操作定级 |

**两个刻意设计**：

- **#5 订阅/代扣横跨 B/C 是有意为之**："识别+提醒"是洞察（绿链路），"取消"是管理动作（黄确认）——同一场景的两个动作各归其类，正好是"同类合并"的最佳注脚；赛题场景名"订阅/代扣管理"保持不变，大厅端**一卡双归**：识别卡挂 B 组（"我有哪些自动扣费"，结论页联动 C 组取消流程）、管理卡挂 C 组（"把不用的订阅都取消掉"）——两卡同带 `#5` 徽标，评委可逐一指认。
- **#6 是编排层而非新工具类**：它的每个子操作（锁资金/定时下单/提醒）全部复用 A/C 既有链路与权限裁决，自身只新增 `scheduled_tasks` 编排与调度器——这正是"跨场景"的题眼，也证明工具抽象能力（隐含评分点）。

### 1.3 工程收益（为什么要合）

| 复用点 | 明细 |
|---|---|
| 前端组件 | ApproveCard / MfaBlock / ReceiptBlock 服务 A+C 全部写操作；ChartBlock / 订阅清单服务 B；TodoDagBlock 服务 D——**六场景只需一套安全交互骨架** |
| 安全链路 | 权限裁决 / 确认卡 / MFA / 审计一处实现，4 组 24 个工具自动继承，LLM 无法绕过 |
| 后端模式 | 写操作 = 幂等+裁决；读操作 = 聚合+分页；定时 = scheduled_tasks+调度器——**三种模式覆盖全部场景**，新增场景只是配置 |

### 1.4 场景大厅随之改版

大厅由"6 卡平铺"改为"**4 组分区**"：组标题（A 资金办理…）下挂场景卡；D 组置顶并带 ⭐ 演示主线标。每卡 = 图标 + 赛题 `#n` 徽标 + 名称 + 一句话卖点 + 1~2 条示例 chip；示例仍全部命中种子数据（doc 03 §9：两个李磊 / 凌晨 ¥4,999 / ¥68 遗忘订阅 / 稳健添利 R2 / 王芳生日），保证"点下去一定演得出来"。视觉风格按 §2 改版为服务宫格；前端组序以 scenarios.ts 导出的 `HALL_GROUP_ORDER = [D,A,B,C]`（D 置顶）为唯一排序来源。

## 2. 前端设计定调：高级简约 · 去 AI 感

### 2.1 核心决策：双层 UI

> **默认是银行，按需是驾驶舱。**

| 层 | 面向 | 形态 |
|---|---|---|
| **默认层 · 管家模式** | 用户 / 演示主线 | 私人银行质感：深色高级基调保留，终端元素退场——无 ⏺/❯ 符号堆砌、无 ASCII 框线、无大面积 mono；圆角精致卡片 + 发丝级分隔线 + 大留白；金额用大号等宽数字（`font-variant-numeric: tabular-nums`）；金色仅用于品牌 ◆ 与关键主按钮。Agent 工作过程默认折叠为一行优雅进度：「正在为您办理 · 第 2/3 步 ▸」，可点开 |
| **透视层 · 透视模式** | 评委 / 技术考察 | `Shift+Tab` 或头部开关切换：TodoDagBlock / ToolCallBlock / StatusBar 安全计数 / TraceDrawer 审计回放全部展开——自主规划可视化、五大安全机制证明等赛题考点集中于此层，视觉沿用 v2.1 已验证的控制台语言，**零返工复用** |

**为什么这样能"去 AI 感"**：用户 90% 时间看到的是银行而不是终端；AI 能力以"结果可靠 + 过程可查"呈现，而不是用技术符号炫耀。评委追问实现细节时一键透视，考点一个不丢。

### 2.3 安全 UI 不变量（风格改版不得松动）

1. 卡片关键数据（金额/收款人/卡号）一律服务端 payload 渲染，LLM 文本永不作为数据源；
2. 倒计时服务端权威（双轨制，本地仅做显示递减）；
3. 快照恢复必须原样保住 pending 确认卡 / MFA 块；
4. 风险色不单独承载语义（图标+文字并行，无障碍要求）。

## 3. 交互逻辑与业务流程（按组定型）

### 3.1 组 A 资金办理（黄/红链路骨架）

```
输入 → guard_in 注入检测 → intent(场景+槽位) → [消歧：同名/缺槽]
→ planner 出 DAG → 权限裁决(静态注册表+动态升级规则)
→ 🟡 确认卡(300s 服务端倒计时) / 🔴 确认卡 → MFA(短信码，3 次失败锁 15min)
→ 执行(Idempotency-Key，重复提交不双扣) → verifier 数字校验 → 回执(trace_id 可回放)
```

- **#1 转账四形态**：普通（黄）／大额·陌生收款人·凌晨（红，doc 02 §8.3 三条动态升级规则）／定时（确认后转 scheduled_tasks）／AA 收款（人数从上下文解析，拆 N-1 笔收款单，黄）。
- **#3 理财三动作**：推荐/对比（绿）→ 申购（先做风险匹配校验，R4 > 用户 R2 直接拒——演示点；匹配则走红 MFA）→ 赎回（同为 🔴，doc 02 §5 定级）。

### 3.2 组 B 洞察分析（绿链路骨架）

```
输入 → intent → 绿色直通(无确认环节) → 聚合 API → 图表卡+文字摘要 → 可多轮追问(带上下文)
```

- **#2 账单**：月账单 → 分类饼图 + 异常高亮（凌晨 ¥4,999）→ 追问"怎么处理" → 无缝转组 C 挂失流程——**跨组衔接是演示加分点**。
- **#5 识别**：订阅清单（5 个，¥68 遗忘订阅标"疑似遗忘"）→ 用户说"取消它" → 转组 C 取消流程。

### 3.3 组 C 卡片与订阅管理（双入口骨架）

```
入口1 对话指令 ／ 入口2 管理页(我的卡片·我的订阅)
→ 状态卡展示 → 选定操作 → 权限裁决(虚拟卡申请=黄 / 调额=黄 / 冻结=黄 / 挂失=红 MFA / 取消订阅=黄)
→ 确认 → 执行 → 状态刷新 + 回执
```

### 3.4 组 D 智能联动（演示主线）

```
"下个月 15 号是我爱人生日，帮我提前准备好"
→ 事件意图(实体=王芳，日期解析) → planner 3 节点 DAG
  [锁定资金 ¥1000(黄确认)] → [创建定时下单：鲜花+蛋糕(生日前2天)] → [创建提醒]
→ 透视模式展示 DAG 逐节点点亮 → scheduled_tasks 落库
→ 调度器到期触发(run-now 可现场演示) → 通知 + 真实支出流水 → 回执
```

### 3.5 全局交互规则（六条）

1. Esc 中断 / 补偿链回退 / 人工接管，全会话生效（doc 02 §7.4）；
2. 会话状态机唯一决定输入可用性与键盘归属（doc 04 §6）；
3. 宫格大厅 chip = 手动输入，不另设协议、不降安全等级（doc 04 §8.7）；
4. 空槽追问、同名消歧、代词解析（"再给她转一次"）由 intent 节点统一处理；
5. 所有写操作回执必带 trace_id，可跳审计回放（答辩杀手锏）；
6. LLM 全挂 → 降级模式：仅关键词直连绿查询，写操作一律婉拒（doc 03 §10）。

## 4. 前后端框架与功能一致性

### 4.1 技术栈（锁定不变）

| 层 | 选型 | 端口 |
|---|---|---|
| 前端 web-app | Vue 3 + Element Plus + ECharts（暗色定制主题） | 8080 |
| Agent agent-service | FastAPI + WebSocket + LangGraph + DeepSeek（OpenAI 协议兼容，可换 Qwen） | 8200 |
| 银行核心 bank-core | FastAPI + SQLAlchemy + SQLite（9 表 + seed.py 幂等种子） | 8100 |
| 部署 | docker-compose 三服务一键起；`scripts/dev.ps1` 本地三进程开发 | — |

### 4.2 功能一致性三铁律

1. **契约唯一**：WS 消息分发表（doc 02 §10.1 = doc 04 §5，共 11 类下行 + 4 类上行）是前后端唯一接口契约。任何新能力的落地顺序固定为：**先改协议表 → 再同时改两端 → 最后更新 §4.3 矩阵**，禁止"先做再说"。
2. **服务端唯一事实源**：金额/余额/卡号/倒计时只从服务端 payload 渲染；前端不做任何金融计算与状态推断。
3. **入口-能力双向可追**：每个前端入口（场景 chip / 管理页按钮 / 对话指令）必须映射到 Agent 工具 + bank-core API；每个工具必须有前端落点。§4.3 矩阵即核对基准，评审与 DoD 检查逐行打钩。

## 5. Agent 框架与各模块职责

### 5.1 LangGraph 图节点（7 节点，签名见 doc 03 §1.2）

| 节点 | 职责一句话 | 输入 → 输出 | 失败策略 | 审计事件 |
|---|---|---|---|---|
| guard_in | 注入双路检测 + 熔断前置检查 | user_text → security_flags | 命中 → 拒答+计数，累计锁定（fail-closed） | decision |
| intent_node | 意图识别 + 槽位抽取 + 歧义判断 | text+上下文 → intent{scenario, slots, confidence, ambiguous} | 超时/解析失败 → 重试≤2 → 降级 chat 兜底 | intent |
| planner_node | 生成子任务 DAG JSON | intent+工具目录 → dag | 校验失败（无此工具/有环）→ 重试≤2 → "换个说法" | plan |
| executor_node | 拓扑调度 + 权限裁决 | dag → dispatch / pending_action | 黄/红 → interrupt 等确认；被拒 → reflector | decision |
| tool_dispatch_node | 调工具打 bank-core | node → node_results | 失败 → reflector 补偿/重试 | tool_call |
| reflector_node | 失败反思 + 补偿链回退 | node_results → retry / compensate / done | 补偿也失败 → 人工接管提示 | decision |
| responder_node | 自然语言汇报 | results → final_reply | verifier 拦截 → 重生成≤2 → 保守话术 | reply |

### 5.2 安全中间件五模块（`security/`，签名见 doc 03 §1.3）

| 模块 | 职责 | 关键点 | 失败方向 |
|---|---|---|---|
| permission.py | 绿/黄/红三级裁决 | 静态注册表 + 三条动态升级规则；独立于 LLM，对话无法覆盖 | 拒绝优先 |
| injection.py | 输入注入双路检测 | 正则规则路 + LLM 分类路；分类器超时以规则路为准 | fail-closed |
| verifier.py | 回复数字 vs 工具结果比对 | 不一致即阻断重生成 | 保守话术 |
| audit.py | trace_id 六类事件全链路 | JSONL 落盘 + SQLite 索引 + /api/audit/{trace_id} | 必写，答辩回放数据源 |
| breaker.py | 异常熔断状态机 | 连败 3 次禁写 / MFA 连败锁 15min / 注入累计 2 次锁定 / 凌晨大额升红 | 锁定优先 |

### 5.3 工具层：7 模块 24 工具（按四组归位，doc 02 §5 为唯一清单）

| 模块 | 工具 | 归组 |
|---|---|---|
| 通用 | query_balance🟢 · query_transactions🟢 · resolve_contact🟢 · change_password🔴 | 支撑 |

### 5.4 支撑模块职责

- **SessionManager（会话网关）**：会话状态机唯一权威；处理 message/confirm/mfa/interrupt 四类上行（doc 03 §1.1）；
- **ChannelAdapter（渠道适配）**：web 流式 / im 降级（"回复 1 确认"），同一 Agent 同一 trace 体系，UI 降级安全不降级（doc 02 §10.2）；
- **Scheduler（调度器，在 bank-core 内）**：asyncio 轮询到期任务 → 按创建时快照执行（"钱和事"都在银行侧）→ `POST /api/internal/notify` 回调 agent-service 推送用户渠道；`POST /api/admin/scheduler/run-now` 供现场演示（doc 03 §6-7）；
- **auth.py**：mock 登录 JWT + 模拟短信 MFA（人脸/U 盾为演示占位，文档明示）。

### 5.5 LLM 职责边界（三做三不做）

| LLM 做 | LLM 不做 |
|---|---|
| 理解：意图/槽位/消歧/代词解析 | 权限裁决（→ permission.py，不可被提示词覆盖） |
| 规划：子任务 DAG JSON | 金融计算（→ bank-core，LLM 不算账） |
| 表达：自然语言汇报与追问 | 数据存取（→ 只能经工具层 API，绝无 DB 直连） |

这是幻觉防护与全链路可审计的架构根基，任何迭代不得突破。

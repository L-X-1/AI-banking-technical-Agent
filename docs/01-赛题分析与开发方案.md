# 银行 AI 智能体（AI Banking Agent）—— 赛题分析与开发方案

> 版本：v1.0　日期：2026-09-22
> 本文档是项目的总纲，后续架构设计、任务拆解均以此为准。

---

## 一、赛题解读

### 1.1 核心命题

国内赛道聚焦 **"AI 代人操作银行"（安全 + 体验）**。参赛团队需构建一个 AI Banking Agent 系统：

- 通过**自然语言对话**理解用户金融意图；
- **自主规划**任务链路并**真实执行**银行业务操作（不是问答机器人）；
- 支持通过 **APP、IM 等渠道**与用户连接；
- 至少覆盖 **3 个核心场景**，鼓励完整覆盖全部 6 个场景。

行业对标：Revolut AIR（AI 银行助手）；可参考 OpenClaw 等开源智能体项目。

### 1.2 六大场景与典型能力

| # | 场景 | 典型能力 | 实施优先级 |
|---|------|----------|-----------|
| 1 | 智能转账 | 按人名/手机号/备注转账、定时转账、拆分 AA 收款 | **P0** |
| 2 | 账单分析 | 消费分类统计、异常交易识别、月度/年度账单报告 | **P0** |
| 3 | 理财操作 | 产品推荐与对比、风险评估、一键申购/赎回 | P1 |
| 4 | 卡片管理 | 卡申请、额度调整、交易限制/解锁、卡片挂失 | **P0** |
| 5 | 订阅/代扣管理 | 自动识别订阅扣费、续费提醒、一键取消订阅 | P1 |
| 6 | 跨场景联动 | 例：检测"我爱人生日"，当月锁定 1000 元活期，生日前 2 天订购鲜花、蛋糕 | P2（杀手锏） |

### 1.3 硬性技术要求（评分关键）

1. **权限分级机制（优先级：高）**
   - 🟢 绿色（自动执行）：余额查询、交易记录查询、账单分析、理财收益查询等纯查询操作；
   - 🟡 黄色（用户确认）：小额转账（日累计 ≤ 1000 元）、订阅取消、虚拟卡申请等，执行前展示操作详情并获得明确确认；
   - 🔴 红色（强验证）：大额转账（日累计 > 1000 元）、密码修改、卡片挂失解挂、理财产品申购等，须通过人脸识别、短信验证码或 U 盾等多因子认证。

2. **安全机制（优先级：高）**：幻觉防护 / 注入防御 / 操作审计 / 异常熔断 / 沙箱环境。

3. **意图理解与任务规划**：支持模糊表达、省略上下文、隐含意图；复杂任务拆解为子任务 **DAG**；执行过程支持**中断、回退和人工接管**。

### 1.5 隐含评分点推断

- **安全工程深度**（权限分级 + 五大安全机制）是区分普通 Demo 与优秀作品的关键；
- 场景覆盖度与工具抽象能力；
- 交互体验（流式响应、确认卡片、可视化账单）；
- 工程完整度（可部署、有测试用例、文档齐全）。

## 二、开发方向

1. **场景全覆盖，分层实施**：P0（转账/账单/卡片）→ P1（理财/订阅）→ P2（跨场景联动）。
2. **跨场景联动作为答辩故事线**："我爱人生日"场景最能体现 Agent 自主规划能力，作为演示视频主线。
3. **安全即卖点**：权限分级为独立中间件，所有工具调用强制经过，Prompt 无法绕过。
4. **自建 Mock Bank Core**：独立模拟银行核心（账户/交易/理财/卡片/订阅 REST API），Agent 只能通过 API 操作，从架构上保证幻觉防护与可审计。
5. **多渠道接入**：渠道适配层（Channel Adapter），Web APP 为主渠道，IM 通过 Webhook 接入。

## 三、技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| LLM | DeepSeek-V3 / Qwen-Max（Function Calling） | 国内可直连、工具调用稳定、成本低、可配置多模型 |
| Agent 框架 | **LangGraph**（Python） | 状态图天然对应 DAG；`interrupt` 原生支持确认/人工接管；checkpointer 支持回退与断点续跑 |
| 后端 | FastAPI + WebSocket | 流式对话、异步工具执行、易与 LangGraph 集成 |
| Mock 银行 | FastAPI 子服务 + SQLite（可升 PostgreSQL） | 独立进程部署，体现隔离与沙箱理念 |
| 前端 | Vue 3 + Element Plus + ECharts | 聊天式银行 APP 界面、确认卡片、账单可视化 |
| 安全组件 | 自研权限策略引擎 + 双路注入检测（正则规则 + LLM 分类器）+ 结构化审计日志（JSONL/SQLite） | 对应五大安全机制 |
| 沙箱 | Docker 受限容器执行生成代码（备选 RestrictedPython） | 对应沙箱要求 |
| 测试 | pytest + 场景测试脚本集 | 交付"测试用例"要求 |
| 部署 | docker-compose 一键起全栈 | 交付"部署说明"要求 |

## 四、总体架构

```
┌────────────────────── 渠道层 ──────────────────────┐
│   Web APP (Vue3 聊天式银行界面)   IM Adapter (Webhook) │
└────────────────────────┬─────────────────────────────┘
                         ▼
┌──────────────────── 会话网关层 ────────────────────┐
│  会话管理 / 用户身份认证 / 渠道协议适配 / 流式推送    │
└────────────────────────┬─────────────────────────────┘
                         ▼
┌──────────────── Agent 核心（LangGraph）─────────────┐
│  意图理解 → 规划器(输出子任务 DAG) → 执行器(拓扑调度) │
│  → 结果反思/自然语言汇报                              │
│  支持 interrupt（用户确认 / 人工接管）与失败回退       │
└────────────────────────┬─────────────────────────────┘
                         ▼   （所有工具调用强制经过）
┌──────────────────── 安全中间件 ────────────────────┐
│  权限分级引擎（绿/黄/红） │ 注入防御（双路检测）       │
│  操作审计（trace_id 全链路）│ 异常熔断（连续失败锁定） │
└────────────────────────┬─────────────────────────────┘
                         ▼
┌──────────────── 工具层（Function Tools）────────────┐
│ 转账 │ 账单分析 │ 理财 │ 卡片 │ 订阅/代扣 │ 跨场景联动 │
└────────────────────────┬─────────────────────────────┘
                         ▼
┌────────────────── Mock Bank Core ──────────────────┐
│  账户 / 交易流水 / 理财产品 / 卡片 / 订阅  REST API    │
│  SQLite 持久化 + 种子数据脚本                         │
└─────────────────────────────────────────────────────┘
```

### 关键机制设计

- **权限分级引擎**：每个 Tool 声明风险等级标签，策略引擎统一裁决——绿→直接执行；黄→生成确认卡片，等待用户明确确认；红→进入多因子认证流程（模拟短信验证码 / 人脸识别占位）。权限判定独立于 LLM，无法被对话内容覆盖。
- **幻觉防护**：系统提示禁止在无工具调用时陈述账户数据；输出校验器比对回复中关键数字与工具返回结果，不一致则阻断重试。
- **注入防御**：输入侧（正则规则库 + LLM 分类器双路检测越狱/越权指令）；数据侧（工具返回内容标记为不可信数据，不进入指令通道）。
- **操作审计**：trace_id 贯穿 意图 → DAG → 每次工具调用 → 用户确认 → 结果，落结构化日志，直接作为安全自评报告素材。
- **异常熔断**：连续失败 N 次或检测到可疑行为模式 → 锁定会话，需人工/强认证解锁。
- **DAG 规划与回退**：Planner 输出 JSON 格式 DAG（节点=子任务，边=依赖），Executor 拓扑调度；节点失败时按补偿动作（compensation）回退，支持用户中断与人工接管。
